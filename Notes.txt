The config file will contain the following:
    - "airflow-task-details": this contains all the spark job names and details that will be executed in the Airflow DAG
        * "spark_details"."spark_kubernetes_args": this dictionary contains the spark configs like "driver_cores", "driver_memory", .... also "pyspark_job_main_file_s3_path" whih needs to be modified to be the spark .py file in this project e.g "s3a://workflows/raw_api_search_spark_load/scripts/sp_api_search_load.py"
        * "s3a://workflows/" is the root path that the project folder is to be deployed in MinIO
        * "spark_dependencies_libraries" contains all the required jar files required for the spark job. jar files can be added in the following path : "/workflows/sys/libs/"
        * "spark_details"."spark_job_args" contains the following arguments that can be modified for each job:
            > "project_dir_name": this is the main project name (Folder name of the project)
            > "output_warehouse_fq_table": target table name in DigiXT (Tirno) e.g. "raw.rmcore.apis_bagtag" where raw is the catalog name and must already exists, rmcore is the schema name in tirno which must be created if not exist in the specified catalog, apis_bagtag is the target table name
            > "output_wh_table_load_strategy": is the loading startegy which can be "merge_upsert" this is Update then insert startegy and it must have the merge_data_join_fields defined, "insert_overwrite" which drops and recreates the iceberg file, "append" which appends in the iceberg file
            > "column_for_incremental" is the source column to check for new data over the target data. it is usually the same as the "partitioning_column"
            > "is_incremental": true for incremental load
            > "auto_table_creation" ture for auto create the table in Trino if table not exists based on the fetched metadata
            > "db_details" contains the argument info for each source table database
    - "airflow-task-dependencies-details": this is in which we can define the dependencies between the defined tasks (which will execute after Start and which will execute after any other task and which after finish will go to end)
    - "airflow-dag-details": this contains the3 dag_id and dag description.
        * The dag_id that is defined in this project must be added in the Airflow variable "AIRFLOW_PIPELINES" by editing it through Airflow Admin UI and you can add a dictionary for this dag_id with its details [catalog, schedule_interval, start_date (if not specified then mapped to 30 days before current), dataset_outlet_flag, retries, retry_delay, tags, task_status_mail_flag (dafaul value = true)] like the following:
            "raw_api_search_spark_load_dag":
            {
                "catalog":"raw",
                "schedule_interval":"45 4 * * *",
                "dataset_outlet_flag":true,
                "tags":["spark","api_search_load"]
            }
        * in the airflow variable "AIRFLOW_DAG_DEFAULT_ARGS" you can add the email to configs like this:
            {
                "email_to":["mostafa.fathy@icp.gov.ae"],
                "email_on_failure":true,
                "email_on_success":true
            }
    - There is a python script that can generate the tasks and their dependencies for the config file

In Airflow when it generates the spark-submit command it adds to it --spark.hadoop.custom.arguments in which it passes a json data with all custom configs and arguments. this "spark.hadoop.custom.arguments" is then read by the method "initialize_read_arguments" using json.loads(sc.getConf().get('spark.hadoop.custom.arguments')).
This initialize_read_arguments returns spark (spark session), sc (spark context), spark_app_name (this is the first argument passed by the airflow generated spark-submit command - these are the keys inside the dict "airflow-task-details" in the config file in config folder), spark_job_args, cluster_details_spark_args, minio_s3_credentials,vendor_credentials
spark_job_args are the configs in the dict "spark_details"."spark_job_args" in each task in the "airflow-task-details" dict in the config file. it is also updated with the following:
    - using this command spark_job_args["python_dependencies_base_paths"] = Constants.DEFAULT_PYSPARK_DEPENDENCIES_LOCAL_PATH if the key "python_dependencies_base_paths" is not mentioned in the config file. DEFAULT_PYSPARK_DEPENDENCIES_LOCAL_PATH = "" by defaul in this project.
    - spark_job_args["dag_id"] = the dag_id that is defined in the config file in "airflow-dag-details"."dag_id"
    - spark_job_args['db_details']['password'] = source_db_password , source_db_password = Variable.get('udb_password', None) -- this will be get from the vault in digiXT
    - The key "catalog_minio_bucket" is also added into "spark_job_args" (this is the bucket name for the defined catalog so if the catalog for this dag_id is "raw" in the AIRFLOW_PIPELINES VARIABLE then the bucket will be "raw" as defined in the "GLOBALS" variable)
